🔄 FLUXO DE DEPLOYMENT:
─────────────────────────────────────────────────────────────────────────────

1️⃣  LOCAL (Sua máquina)
    $ git add .env.example
    $ git add DEPLOYMENT.md
    $ git commit -m "Add deployment guide"
    $ git push origin main
    
    ✓ Commit APENAS do .env.example (sem valores sensíveis)
    ✓ .env NÃO é commitado (está no .gitignore)

2️⃣  VPS (Remote)
    $ git clone seu_repo
    $ git pull origin main
    
    ✓ Recebe apenas .env.example
    ✓ Não recebe arquivo .env

3️⃣  VPS - ADICIONAR VARIÁVEIS SENSÍVEIS
    
    Opção A - Via SCP (mais segura):
    ──────────────────────────────
    Na sua máquina local:
    $ scp .env seu_usuario@vps:/var/www/v6_agente_ia/
    
    Na VPS:
    $ chmod 600 .env
    $ ls -la .env
    
    
    Opção B - Manualmente via Nano (se necessário):
    ────────────────────────────────────────────────
    Na VPS:
    $ cp .env.example .env.local
    $ nano .env.local
    # Colar as credenciais reais aqui
    $ chmod 600 .env.local
    
    
    Opção C - Variáveis de Ambiente do Sistema:
    ───────────────────────────────────────────
    Na VPS, editar o arquivo systemd service:
    $ sudo nano /etc/systemd/system/agente-ia.service
    
    [Service]
    Environment="SUPABASE_URL=https://..."
    Environment="GOOGLE_SERVICE_ACCOUNT_PRIVATE_KEY=..."
    # ... etc

💡 DICAS EXTRAS:
─────────────────────────────────────────────────────────────────────────────
1. Faça backup de .env em local seguro antes de fazer deploy
2. Use .env.local para sobrescrever valores em desenvolvimento
3. Configure alertas se o arquivo .env for modificado sem autorização
4. Rotacione credenciais periodicamente (trimestral)
5. Nunca coloque .env em rede compartilhada (NFS, SMB, etc)
